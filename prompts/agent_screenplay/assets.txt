# Skill: 素材挖掘

## 描述
这是一个**原子素材识别 + 素材深化设计 Skill**。可以直接调用本 Skill，抽取后续制作所需的关键素材，并直接输出带完整描述的素材清单。

## 目的
从输入内容中系统挖掘并结构化输出以下素材：
- 所有角色
- 所有重要物品 / 道具
- 营销场景中的产品
- 所有重要场景

本 Skill 的输出是**可直接给后续参考素材生成使用的描述型素材清单**。

## 核心原则

### 1. 输出全量重要素材，不做流程假设
- 只根据当前输入内容本身挖掘素材。
- 不因为“后面可能还会补”而省略已明确出现的重要素材。

### 2. 角色要列“主体”和“变体”
- **主体**：角色默认、稳定、最常用的核心形象，且**必须等于对应变体列表中的第一个版本**。
- **变体**：同一角色在年龄、伤势、妆造、身份伪装、服装方案、非人化等方面发生**巨大且稳定**变化的版本，只保留可复用的强差异版本。
- **人物穿在身上的服装默认属于角色服装设计的一部分**，应归入角色的主体或变体，不应误拆到“物品”里。

### 3. 用户已上传参考图优先复用
- 若输入中已有用户上传的图片（对话素材清单里的 `图1 / 图2 …`），则该资产视为“已上传参考图”。
- 已上传参考图的资产，不再重复挖掘为新的主体条目；但其角色/物品/产品/场景身份仍需保留在素材清单中。
- 已上传参考图的资产，仍需继续挖掘其角色变体、包装变体、场景变体等可复用版本。
- 输出中凡是引用已上传参考图，都必须写成 `{素材名}`，禁止改写成普通名称。
- 若用户上传了图片，但用户没有明确说这个形象要沿用（只是提供参考），则该资产记为“用户已上传参考图（要求重画）”。
- 即使某张上传图内容看起来就是主角形象、主场景定板或产品主体，只要用户还没确认沿用，也必须记为“用户已上传参考图（要求重画）”，禁止擅自写成“用户已上传参考图（确认沿用）”。
- “参考图”只是普通称呼，不等于“确认沿用”。禁止出现这类推理：`用户提供了参考图，而且它对应主角 / 主场景 / 主产品，所以主体来源是用户已上传参考图（确认沿用）`。
- **素材清单必须显式标注主体来源**：对每个角色 / 物品 / 产品 / 场景条目，都要明确写出该资产是“用户已上传参考图（确认沿用）”“用户已上传参考图（要求重画）”还是“待生成主体”，禁止让后续环节自行猜测。

## 挖掘规则

### 一、角色挖掘规则

#### 1. 必须纳入角色清单的情况
- 所有主角
- 所有配角
- 所有有台词角色
- 所有推动剧情或卖点表达的功能角色
- 所有在画面中出现多次需要稳定形象的角色
- 营销脚本中承担展示、讲解、试用、对比、见证功能的人物

#### 2. 群体背景角色默认不挖**：
- 背景宾客、围观群众、路人群体、课堂同学群、店内顾客群、舞台下观众群、下人群体这类只承担环境填充或群像氛围的角色，不进入素材清单
- `小队队员`、`士兵们`、`随行下属`、`宾客们`、`围观群众`、`黑衣人一行` 这类群体称呼，默认也**不能**作为一个角色条目写进素材清单，更不能写成 `主体来源：待生成主体`

若群体中存在明确分工或镜头会给到清晰辨识，则仍需拆出，例如：
- 保安A / 保安B
- 面试官1 / 面试官2
- 同事甲 / 同事乙

#### 3. 角色主体与变体拆分规则
每个角色都要输出：
- **主体**：默认形象，且必须等于对应变体列表中的第一个版本
- **变体**：只列**除主体外**的其他巨大差异版本，必须是稳定、可复用、会显著改变整体视觉识别的版本

注意：
- **变体只保留差异巨大的版本**：只有年龄、伤势、非人化、身份伪装、成套服装方案、整体妆造等发生显著且稳定的整体变化，才算变体
- 以下才属于应挖掘的角色变体示例：童年版、老年版、严重受伤版、重度烧伤版、明显怀孕版、截然不同的服装版、截然不同的伪装身份版、非人化版本
- 以下都**不算变体**：姿势变化、动作过程、受力结果、表演调度、临时受限状态，轻微情绪、短时表情、普通姿态、一般持物、轻微脏污、轻微疲惫、普通哭泣 / 微笑、普通淋湿、戴摘普通配饰等；“紧张害羞版”“慌乱跑开版”“回头看版”“抬手版”“坐下版”“双手被绑版”“跪持灵位版”“被打摔倒版”“手腕勒红版”“被打趴版”“持灵位拐杖版”“持剑对峙版”等，**都不算角色变体**
- **排序规则**：主体单独列出；变体列表里不要重复主体

### 二、物品 / 道具挖掘规则

### 0. 物品挖掘总原则
- **只挖值得单独做参考素材的稳定物品，不要贪多**
- 物品清单的目标是服务后续参考素材生成，不是把画面里出现过的所有东西都列出来
- **一次性动作道具默认不挖**：若某物只是为某个瞬时动作服务，如临时凶器、一次性攻击工具、顺手抄起的杂物、短暂递出的生活物件，且后续不需要稳定复用，则不要进入素材清单

### 1. 必须纳入物品清单的情况
- 关键剧情道具
- 明确被镜头强调的物品
- 前后反复出现、且需要保持外观一致的物品
- 营销内容里用于演示功能、形成对比、体现卖点的物品
- 若某物只是陪衬环境、一次性路过、普通生活填充、可由模型自由生成替代，则**默认不挖**，以下情况默认**不要挖**：
  - 普通环境杂物：杯子、纸张、书堆、路边摆件、桌面零碎文具、墙上装饰画、窗帘、餐具、花瓶等
  - 一次性出现且不影响后续连贯性的随手物件
  - 仅用于丰富生活气息、但不影响角色行为和剧情理解的填充物
  - 仅作为背景存在、没有被镜头重点强调、没有明确交互的陈设

#### 1.1 从严筛选规则
- 即使物品在文本里出现了，也**不代表必须进入素材清单**
- 只有当该物品既重要、又值得单独做稳定参考时，才纳入；**如果删掉这个物品，不影响后续独立生图或镜头衔接，就默认不挖**
- 优先判断三件事：
  - 是否会前后反复出现，必须保持一致
  - 是否有明确独特外观，不能交给模型自由泛化
  - 是否会被交接、寻找、保留、损坏、发现，成为后续持续存在的关键道具
- **若某物只是一次性触发剧情结果，但后续不再作为独立资产存在，则默认不挖**
- **口头提及但当前未实际出现的未来对象，不算当前素材**：如果角色只是说“待会儿去吃肉包子”“明天去买花”“下次送你蛋糕”，但当前文本里没有实际出现、展示、携带、使用、看到这些对象，则不要挖成物品
- 判断标准是：该物品是否已经在当前剧情阶段被明确呈现、交互或成为当前镜头 / 当前段落的现实组成部分；若只是计划、想象、回忆、聊天提及、未来打算，则先不挖
- **镜头里出现不等于要挖**：只因某物被角色拿着、桌上放着、画面扫到、顺手使用，就默认不挖
- **默认排除项再强化**：普通杯子、文具、餐具、桌面摆件、随手文件、路边袋子、背景书本、普通手机壳、装饰花束、窗帘、台灯、零食、水瓶等，只要不是剧情关键物，一律默认不挖
- **明确排除示例**：女主杀死太监时使用的银针、临时刺人的发簪、顺手抄起的烛台、一次性泼出的药碗，这类只服务单次动作的道具，若后续不再持续出现或被当作证据物保留，则不要挖

#### 1.2 服装与物品的归类边界
- **服装不是物品**：人物已经穿在身上的校服、婚衣、嫁衣、外套、礼服、工作服、盔甲等，默认都属于角色主体或角色变体，不归入“物品”
- 例如：
  - `女款嫁衣` 若是陆青野穿在身上的嫁衣，应写入陆青野的服装设定，不应输出为物品
- 只有当服装**脱离人物身体、作为独立可复用对象存在**时，才可以归入“物品 / 道具”

### 2. 物品变体规则
以下变化应作为物品变体记录：
- 开 / 关
- 完整 / 破损
- 空 / 满
- 点亮 / 熄灭
- 包装前 / 包装后

以下变化**不要**作为物品变体记录：
- 在手中 / 在桌上 / 掉地上 / 供桌摆放 / 被举起 / 被拿起 / 被握在手里
- 放在课桌角 / 放在桌上 / 放在椅背上 / 掉在地上
- 被拿起 / 被摇晃 / 被递出 / 被握在手里
- 飘在空中 / 落在桌上 / 飞进教室
- 因镜头调度产生的位置变化、动作变化、受力过程、运动轨迹
- 只在单个镜头中成立、无法作为稳定独立素材复用的瞬时状态
- 例如：
  - `灵位` 的“供桌摆放版”“手持版”不算物品变体

注意：
- 物品变体只列稳定版本，不写镜头摆放位置类伪变体
- 若物品存在多个版本，**主体必须取变体列表第一个版本**
- **不要把人物穿在身上的服装当作物品主体或物品变体输出**
- **不要把对白里提到、但当前尚未出现的未来物品挖出来**
- **不要把一次性动作道具挖出来**：若某物只在单个动作里短暂成立，且后续不再需要稳定复用，如一次性凶器、临时攻击工具，则不要进入素材清单
- **宁缺毋滥**：如果一个物品是否重要拿不准，默认先不挖；
- **复核铁律**：输出物品清单前，必须逐个自查“这个物品是否真的对剧情有重要作用”；若答案不是明确“是”，就删掉，不要保留为凑数物品

### 三、产品挖掘规则（营销类强制）

#### 1. 必须单列产品清单
只要输入是营销、带货、广告、品牌传播、产品演示相关内容，就必须输出**产品清单**

#### 2. 必须纳入产品清单的情况
- 主推产品
- 套装中的核心产品
- 关键 SKU / 型号 / 口味 / 包装规格
- 需要单独展示的赠品、礼盒、替换装（若脚本明确重要）
- 当前剧情阶段已实际出现、展示、试用、讲解、对比的产品

#### 3. 产品与普通物品的区分
- 以卖点传播、品牌识别、购买转化为核心的对象，归入**产品**
- 仅作为使用环境里的辅助道具，归入**物品**
- 若产品存在多个包装 / 规格 / 版本，**主体必须取变体列表第一个版本**

### 四、场景挖掘规则

#### 0. 场景挖掘总原则
- **只挖重要故事场景，不要贪多**：场景清单的目标是服务剧情表达、镜头一致性和后续参考素材生成，不是把所有经过的地点、镜头角落、过渡空间都列出来
- 判断一个场景要不要挖，优先看它是否同时满足以下任一条件：
  - 承载关键剧情事件
  - 承载人物关系变化或情绪转折
  - 承载重要动作结果或关键道具交互
  - 在营销内容中承担使用场景、痛点场景、对比场景、品牌展示场景

若某场景只是过渡通道、背景陪衬、短暂掠过的地点，则**默认不挖**

#### 1. 必须纳入场景清单的情况
- 发生关键剧情或关键卖点表达的场景
- 角色首次出现、关系变化、动作转折、产品展示所在场景
- 营销内容中的使用场景、痛点场景、对比场景、品牌场景

#### 2. 场景拆分规则
当同一大场景内部存在以下差异时，需要拆成不同场景变体：
- 空间功能不同
- 视觉结构不同
- 天气发生明显且稳定的整体变化
- 镜头机位逻辑明显不同
- 用途不同

例如：
- 客厅-沙发区 / 客厅-餐桌区
- 医院-面试室 / 医院-走廊
- 卧室-梳妆台 / 卧室-床边
- 展会-品牌展台 / 展会-体验区
- 晴天庭院 / 暴雨庭院 / 大雪庭院
- 白天营业中的店铺外景 / 深夜打烊后的店铺外景

若同一场景存在多个版本，**主体必须取场景变体列表第一个版本**。只因人物动作不同、镜头里有无拿着某物、同一空间内花瓣飘过、天空微微变暗、云层略厚、普通室内亮度轻微波动等模型可自行生成的细小变化，**都不算场景变体**
- **宁缺毋滥**：如果一个场景是否足够重要拿不准，默认先不挖；

## 五、素材深化设计规则

### 1. 设计总原则
- 本阶段必须覆盖 `素材清单` 中的所有主体和所有变体，不得只挑“核心素材”设计
- 输出的是**结构化设计清单**
- 输出时采用“`版本名：对应完整描述`”的直接写法
- 变体描述必须把**变化点写具体**：要明确写出“哪里发生了变化、变成什么样、哪些核心部分保持不变”，不能只写“治愈版”“受伤版”“雨天版”“节日版”这类空标签
- **无则不写**：若某角色没有变体，则不输出 `变体` 这一行；若某物品 / 产品 / 场景没有变体，则不输出 `变体` 这一行
- 若某角色、旁白或拟人化产品属于有声主体，则其音色描述也必须直接写入对应条目中。
- 若某资产已由用户上传参考图提供，则主体引用必须写成 `{素材名}`，并将其视为后续生成该资产变体时的默认主体来源。

### 2. 角色设计
- **目的**：定义每个角色主体与全部角色变体的核心视觉设定，作为后续角色主体图与角色变体图生成的唯一设计依据
- **面孔默认值**：除非背景明确要求，否则人物默认为亚洲面孔
- **三视图要求**：单体角色的主体和每个单体角色变体描述，都必须足以直接支持后续三视图生成（从头到脚描述，要包括到足部的描述）
- **音色要求**：若该角色在后续流程中需要说话、旁白、发声或承担拟人化表达，则需要在该角色条目下直接补充 `音色描述`
- **输出字段**：
  - `性别`：`男` / `女` 
  - `主体来源`：`用户已上传参考图（确认沿用）` / `用户已上传参考图（要求重画）` / `待生成主体`
  - 若 `主体来源` = `用户已上传参考图（确认沿用）` 或 `用户已上传参考图（要求重画）`，则必须额外输出 `对应素材`：`图1`
  - `主体`：`版本名：完整角色描述`
  - `变体`：`版本名：对应角色变体描述`
  - `音色描述`：`性别__，年龄__，语调__，音高__，语速__，口音无`
- **设计要求**：
  - 明确 4-6 个关键识别特征
  - 不同角色必须主动拉开差异，至少在性别、脸型 / 五官、发型、体型、穿搭气质中拉开多个维度，避免“只是换衣服的同脸角色”
  - 角色描述必须显式写性别，并覆盖面部信息；面部至少写清脸型、眉眼特征、鼻 / 唇特征中的多个维度
  - 角色描述必须覆盖头发 / 面部五官 / 上身服装 / 下身服装 / 鞋或赤脚等足部信息，不能只写到膝盖或小腿
  - 若角色来自 `用户已上传参考图（要求重画）`，可在脑中参考该图片提炼外观特征，但写入 `主体` / `变体` 时，必须只写提炼后的角色描述，不能写“参考图1的女生外貌”这类句子
  - 角色变体必须只保留差异巨大的稳定版本，优先考虑：童年版、老年版、严重受伤版、重度烧伤版、明显怀孕版、截然不同的服装版、截然不同的伪装身份版、非人化版本
  - 角色变体要写清具体改动部位与结果，如“上身改为深色羽绒服、下身改为牛仔裤、足部改为短靴”或“左脸颊割伤已愈合、纱布拆除、皮肤恢复完整，仅保留极浅疤痕；其余五官、发型、服装不变”，不要只写“冬装版”“治好了”“恢复版”
  - 若某角色没有变体或音色需求，则对应字段不写出

### 3. 物品设计
- **目的**：定义所有物品主体与全部物品变体
- **分类要求**：
  - `静态陈设 (Static Prop)`：属于场景环境一部分的物品，后续需要整合进场景设计
  - `动态道具 (Dynamic Prop)`：角色会携带、拾取、使用的物品
- **完整性要求**：每个物品的描述都必须完整自包含，严禁使用“同上”“与XX一样”
- 物品变体必须写清楚具体变化部位与保持不变部分，例如“刀刃缺口修复、表面划痕消失，刀柄材质与比例不变”，不要只写“修复版”
- **输出字段**：
  - `主体来源`：`用户已上传参考图（确认沿用）` / `用户已上传参考图（要求重画）` / `待生成主体`
  - 若 `主体来源` = `用户已上传参考图（确认沿用）` 或 `用户已上传参考图（要求重画）`，则必须额外输出 `对应素材`：`图1`
  - `分类 `：xxxx
  - `主体`：`版本名：完整物品描述`
  - `变体`：`版本名：对应变体描述`
  - `物品类别`：xxxx
  - 若无变体，则不输出 `变体`

### 4. 产品设计（营销类强制）
- **目的**：定义所有产品主体与全部产品变体，确保后续产品展示一致
- **文字信息要求**：
  - 若用户上传产品参考图：必须完整提取品牌名、型号、logo文字、参数、卖点等，形成 `产品文字信息清单`
  - 若用户未上传产品参考图：必须完整提取用户文字描述中的产品核心信息
- **三视图要求**：产品主体和每个产品变体的设计，都必须足以直接支持后续三视图生成
- 产品变体必须明确写出变动发生在包装、规格、口味、外盒、瓶身哪里，以及哪些品牌文字 / logo / 型号保持不变，不能只写“节日版”“礼盒版”
- **输出字段**：
  - `主体来源`：`用户已上传参考图（确认沿用）` / `用户已上传参考图（要求重画）` / `待生成主体`
  - 若 `主体来源` = `用户已上传参考图（确认沿用）` 或 `用户已上传参考图（要求重画）`，则必须额外输出 `对应素材`：`图1`
  - `产品文字信息清单`：xxxx
  - `主体`：`版本名：完整产品描述`
  - `变体`：`版本名：对应产品变体描述`
  - `产品类别`：xxxx
  - 若无变体，则不输出 `变体`

### 5. 场景设计
- **生成的是场景图设计，其中不允许包含任何人物**
- **目的**：定义所有场景主体与全部场景变体的环境、氛围和视觉元素
- **核心规则**：
  - 整合该场景下所有 `静态陈设`
  - 静态陈设的基础设定必须直接嵌入到场景描述中
  - 必须保持空镜，不写角色
  - 场景描述必须更详细，不能只写泛泛地点名词；要结合故事情节，把该场景承担的剧情功能、时间段、天气 / 光线、空间结构、关键陈设、可见痕迹与氛围写清
  - 场景变体必须明确写清楚变化落在什么维度上，如“地面积水消失、窗外雨幕停止、冷色夜灯改为晨间自然光，其余空间结构与陈设不变”，不能只写“晴天版”“白天版”“恢复版”
- **输出字段**：
  - `主体来源`：`用户已上传参考图（确认沿用）` / `用户已上传参考图（要求重画）` / `待生成主体`
  - 若 `主体来源` = `用户已上传参考图（确认沿用）` 或 `用户已上传参考图（要求重画）`，则必须额外输出 `对应素材`：`图1`
  - `主体`：`版本名：完整场景描述（嵌入静态陈设描述）`
  - `变体`：`版本名：对应场景变体描述（嵌入静态陈设描述）`
  - 若无变体，则不输出 `变体`

### 6. 音色描述规则
- 若存在角色台词、旁白、拟人化产品发声等有声主体，则必须在对应主体条目下直接输出 `音色描述`
- 音色描述格式固定为：
  - `性别__，年龄__，语调__，音高__，语速__，口音无`
- 年龄必须是精确整数
- 若同一视频中存在多个声音主体，各主体音色必须显著差异化，至少 4 个字段显著不同，除非用户明确要求同音色
- 音色设计不能只做轻微微调；要尽量拉大角色之间的感知差异，优先拉开年龄层、语调气质、音高、语速，必要时连性别表达也要明确区分
- 角色音色默认挂在对应角色条目下；若是独立旁白或无法归属到具体角色的声音主体，可单独新增 `角色：旁白` 或 `角色：品牌旁白` 等条目承接音色描述

## 输出约束
- 必须覆盖所有重要素材，不得漏掉配角、关键道具、主产品、关键场景
- 物品只列重要道具，不要把普通背景杂物、一次性填充物、普通陈设大量写进清单
- 场景只列重要故事场景，不要把过渡空间、背景角落、机位差异下的局部位置大量写进清单
- 角色只输出统一字段 `主体 / 变体`，不要再拆成 `服装变体 / 状态变体`
- 群体角色不得作为一个 `待生成主体` 条目输出；像 `小队队员`、`宾客们`、`同学们` 这种群体称呼，要么拆成单体角色，要么不进素材清单
- 角色变体必须是巨大、稳定、可复用的差异版本；人物发光、轻微脏污、普通淋湿、普通动作变化都不算角色变体
- 场景变体必须是明显且稳定的空间 / 天气；天空微微变暗、普通亮度波动等不要单独挖成场景变体
- 角色条目必须显式输出 `性别`，且角色描述必须包含具体面部设计并主动拉开角色差异
- 场景描述必须详细到可直接用于后续场景空镜生成，并且要结合故事情节写出剧情相关环境信息
- 营销内容必须单列“产品”
- `素材清单` 必须同时承担“素材识别结果”和“参考素材清单”两种职责
- `素材清单` 必须出现在模型最终输出中，不允许仅在 thinking / 思考中整理后不展示
- `素材清单` 中每个资产都必须显式输出 `主体来源`
- 若 `主体来源` 为 `用户已上传参考图`（确认沿用 / 要求重画），必须显式输出 `对应素材`，写该图的编号（如 `图1`）
- 错误写法：`女主：用户提供了参考图，是主角，主体来源是用户已上传参考图（确认沿用）`
- 正确写法：`女主：用户提供了普通参考图，对应主角外观；用户未确认沿用，因此主体来源是用户已上传参考图（要求重画），对应素材是图1`
- 错误写法：`小队队员 / 类型：功能角色 / 主体来源：待生成主体 / 主体：20-30岁的年轻男女……`
- 正确写法：`若只是群体氛围角色，则不输出；若确需稳定呈现，则拆成队员A、队员B等单体角色分别输出`
- 版本描述必须直接写在 `主体 / 变体` 后面
- 若某类变体不存在，则该字段不要输出，不要写“无”
- 若存在有声主体，必须把 `音色描述` 直接输出在对应角色条目下。
- 不生成参考图 prompt
- 不进行跨 Clip 隐式道具补件
